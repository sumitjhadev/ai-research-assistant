The Problem

Generic chatbots answer confidently — even when they're wrong.

Researchers waste hours manually searching, reading, and cross-referencing dozens of papers to answer a single question. Meanwhile, plugging in a generic LLM makes things worse in a subtle way: it will happily invent plausible-sounding facts, numbers, and citations rather than admit it doesn't know.

"Just add an LLM" doesn't fix this. You need retrieval that's grounded in real sources, and a generation layer that is forced to stay honest about what it does and doesn't actually know.

"According to Smith et al. (2023), this method achieves 94.2% accuracy on the XYZ benchmark."

— paper doesn't exist. Number is fabricated.

"There is not enough information in the corpus to answer this confidently." [declined]

— what this system does instead.

Features

Built for trustworthy research, not demos

Real arXiv Search

Title, authors, abstract, publish date, PDF URL, and arXiv ID for every result — queried live against the public arXiv API.

Graceful PDF Ingestion

Failed downloads or unreadable pages are logged and skipped per-paper — one bad PDF never crashes the whole pipeline.

Metadata-Tagged Chunking

~800 char sliding-window chunks with ~150 char overlap, each carrying paper_id, title, authors and source URL.

FAISS Semantic Retrieval

all-MiniLM-L6-v2 embeddings in a FAISS IndexFlatIP index — cosine similarity via L2-normalized vectors.

Citation-Grounded QA

Every claim must cite [paper_id]. Citations are cross-checked against retrieved sources; weak evidence triggers an explicit "not enough information" response.

Per-Paper Summaries

Structured breakdown of Methodology, Dataset, Key Results, and Limitations for any single paper in the corpus.

Multi-Paper Comparison

Compare 2–5 papers side-by-side in a markdown table: Method, Dataset, Model, Results, Limitations.

Evaluation Harness

A labeled 40-question set measures Recall@5 and retrieval latency (avg + p95), exported to JSON.

Production Hardening

Retry + exponential backoff, structured logging, Pydantic validation, response caching, rate limiting, Docker, and CI — all with mocked LLM calls in tests.

Quickstart

Running locally in under five minutes

terminal 
git clone https://github.com/<your-username>/ai-research-assistant.git
cd ai-research-assistant

python3.11 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # add your GOOGLE_API_KEY

python backend/ingest.py --query "retrieval augmented generation" --max-results 50
python backend/vectorstore.py build

uvicorn backend.api:app --reload --port 8000
streamlit run app.py

Full setup, Docker instructions, and deployment guides live in the project README.
